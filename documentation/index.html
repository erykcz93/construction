01 Introduction

Thank you for choosing Aldervane, a premium HTML5 template for construction companies, general contractors, builders and renovation firms. It contains 13 pages and a working PHP contact form. It is built with plain HTML, CSS and vanilla JavaScript, so there is nothing to install, compile or update.

Demo content: All company names, persons, testimonials, statistics and project descriptions included in this template are fictional demo content and should be replaced by the end user.

Highlights

  • All colours, fonts, spacing and sizes are controlled from assets/css/variables.css.
  • Responsive, mobile-first layouts, tested at 320, 360, 375, 390, 414, 480, 768, 1024, 1280, 1440 and 1920 px.
  • Built to WCAG 2.2 AA practices: keyboard navigation, visible focus, checked colour contrast, reduced-motion support and screen-reader friendly components.
  • No inline JavaScript or CSS, one JavaScript file per feature, and no external libraries.
  • Secure PHP contact form: CSRF token, honeypot, rate limiting and header-injection protection.
  • SEO-ready: unique titles and descriptions, Open Graph and Twitter/X cards, canonical URLs, sitemap, robots file and structured data.
  • All icons and illustrations are original. The only external resource is Google Fonts.

Browser support

Current versions of Chrome, Edge, Firefox and Safari on desktop, Safari on iOS and Chrome on Android. Internet Explorer is not supported.

03 Installation

Preview on your computer

You can open index.html directly in a browser to look around. The contact form needs PHP, so use a local server to test everything:

# Inside the construction-template folder:
php -S localhost:8000
# then open http://localhost:8000 in your browser

No PHP installed? Download it from php.net, or use a local server package such as XAMPP, MAMP or Laragon. To preview the pages only (without the form), any static server works, for example python3 -m http.server 8000.

Publish your website

  1. Replace the demo content: texts, contact details and images.
  2. Configure the contact form (see Contact Form Configuration).
  3. Replace https://www.example.com with your domain (see SEO Configuration).
  4. Upload the files to the public folder of your hosting (often public_html or www) with your host's file manager or an FTP/SFTP client. Upload everything except the documentation/ folder.
  5. Visit your domain and send a test message through the contact form.

The .htaccess files are hidden on some systems. Make sure your FTP client shows hidden files so they are uploaded too. They are optional and only used by Apache servers.

04 Editing Company Name

The fictional demo company is called Aldervane Construction. The quickest way to rename it is your code editor's Find and Replace in files feature (for example in VS Code: Ctrl/Cmd + Shift + H):

  1. Replace Aldervane Construction with your full company name.
  2. Replace the remaining Aldervane occurrences, such as the logo text, the large outlined footer wordmark and the About page title.

The name appears in:

  • the logo text in the header and footer of every page: <span class="logo__name"> and <span class="logo__tagline">;
  • the decorative footer wordmark: <p class="site-footer__wordmark" aria-hidden="true">;
  • page titles, og:site_name and the copyright line;
  • the structured data in the <head> of index.html;
  • site.webmanifest (name and short_name);
  • php/config.php (recipient_name) and the consent text of the forms.

Contact details

Replace the demo phone number +1 (202) 555-0147, the tel:+12025550147 links, the email hello@example.com, the address 1250 Foundry Avenue… and the opening hours in the same way. They appear in the top bar, the mobile menu, the footer, index.html, contact.html and the sidebars. Social profile links are in the footer, marked with the comment Social profiles.

05 Changing Logo

The logo has two parts: a square mark (assets/images/logo/logo-mark.svg) and live text. The text makes renaming easy and always matches the site font.

Option A — replace only the mark

Save your square symbol as assets/images/logo/logo-mark.svg (SVG recommended; a 96 × 96 px PNG or WebP also works if you update the file name). It is displayed at 40 × 40 px.

Option B — use a complete logo image

Replace the content of the .logo link in the header and footer of each page:

<a class="logo" href="index.html">
    <img src="assets/images/logo/logo.svg" alt="Your Company" width="180" height="40">
</a>

Use a meaningful alt text (your company name). If the footer background is dark, use a light version of your logo there, for example logo-light.svg.

Keep the colours accessible

  • Primary buttons use dark text (--color-primary) on --color-accent. Keep a contrast ratio of at least 4.5:1 between them. If you choose a dark accent colour, change the text colour of .btn--primary in components.css to white.
  • --color-accent-strong is used for small accent-coloured text on light backgrounds and needs at least 4.5:1 against --color-background and --color-surface.
  • Form field borders (--color-border-strong) need at least 3:1 against the background.
  • You can check contrast with any online WCAG contrast checker.

Dark sections

Add the class theme-dark to any section to switch it to the dark colour scheme. Components inside adapt automatically. Add bg-grid for the subtle blueprint grid.

Colours inside images

The SVG illustrations and icons have their own colours because they are image files. Icons are drawn in #14202b and turn white automatically inside theme-dark sections. To recolour an icon set, find and replace #14202b in assets/icons/*.svg. The illustrations are placeholders meant to be replaced by photos (see Replacing Images). Also update theme-color in the page heads and the colours in site.webmanifest.

07 Changing Google Fonts

Two families are used: Archivo for headings and Inter for text. To change them:

  1. Choose fonts on fonts.google.com and check that their license allows commercial use (most use the SIL Open Font License).
  2. Replace the Google Fonts stylesheet link in the <head> of every page: 
    <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Archivo:wght@600..800&amp;family=Inter:wght@400..700&amp;display=swap">
  3. Update the font tokens in assets/css/variables.css: 
    --font-heading: "Your Heading Font", "Helvetica Neue", Arial, sans-serif;
--font-body: "Your Body Font", system-ui, -apple-system, "Segoe UI", Roboto, Arial, sans-serif;
  4. Keep &display=swap in the URL so text stays visible while fonts load.
  5. Update licenses/THIRD_PARTY_NOTICES.md with the new fonts and their licenses.

Self-hosting the fonts (recommended for strict privacy requirements)

Loading fonts from Google sends visitors' IP addresses to Google. To avoid this, host the fonts yourself:

  1. Download the font files (WOFF2 format) and keep the license file (OFL.txt) that comes with them.
  2. Put them in a new folder such as assets/fonts/.
  3. Create assets/css/fonts.css with @font-face rules (include font-display: swap;) and link it before variables.css.
  4. Remove the two preconnect links and the Google Fonts stylesheet link from every page.
  5. Remove the Google Fonts item from the privacy policy and update the third-party notices.

08 Editing Navigation

The main menu is inside <nav class="site-nav" id="site-nav"> near the top of every page. The same markup is used for the desktop bar and the mobile menu, so there is only one list to edit per page.

<li class="site-nav__item"><a class="site-nav__link" href="about.html">About</a></li>
  • Mark the current page with aria-current="page" on its link. This highlights it visually and tells screen readers which page is open.
  • The desktop menu appears from 1200 px. If you add many items, check that they still fit, or change the 75em breakpoints in layout.css and navigation.js together.
  • The mobile menu also shows a quote button and contact links (.site-nav__extra).
  • Footer links are in <nav class="site-footer__col"> blocks at the bottom of every page.

Because this is a static template, the header and footer are repeated on each page. Use "Find and Replace in files" to update them all at once.

09 Editing Text

All content is plain HTML. Every section starts with a comment such as <!-- Services -->, so it is easy to find in the file.

  • Headings: each page has one <h1>. Sections use <h2> and cards use <h3>. Keep this order; do not skip levels to get a smaller font size. Use CSS instead.
  • Section labels: the small labels above headings (for example "02 — What we do") use <p class="eyebrow"><span class="eyebrow__index">02</span>What we do</p>. The number is optional.
  • Statistics: the counters use the final value both in the text and in data-counter. Update both, for example <span data-counter="640">640</span>. For decimals add data-decimals="1".
  • Meta tags: each page has its own <title>, meta description and Open Graph and Twitter texts in the <head>. Update them when you change the page content.
  • Reveal animation: add data-reveal to an element to fade it in when it scrolls into view, or remove the attribute to disable it.

How to replace an image

  1. Export your photo at the recommended size, compressed as WebP (quality 75–82 is usually enough) or AVIF.
  2. Put it in the same folder, for example assets/images/projects/cedar-row.webp.
  3. Update the src, width, height and alt attributes. Keeping the width and height of the new file prevents layout shift.
<img class="project-card__image" src="assets/images/projects/cedar-row.webp"
     alt="Three new terraced townhouses with timber cladding"
     width="1200" height="900" loading="lazy" decoding="async">

To offer AVIF with a WebP fallback, use a <picture> element and keep the same class on the <img>:

<picture>
    <source srcset="assets/images/projects/cedar-row.avif" type="image/avif">
    <img class="project-card__image" src="assets/images/projects/cedar-row.webp" alt="…" width="1200" height="900" loading="lazy" decoding="async">
</picture>
  • Keep loading="lazy" on images below the fold. Do not lazy-load the first large image of a page (hero, banners). The homepage hero uses fetchpriority="high".
  • Alt text should describe what the photo shows. Use alt="" only for decorative images, or when the same information is written next to the image. Team photos use alt="" because the person's name appears right below.
  • Cards crop images automatically (object-fit: cover), so a slightly different ratio still fits.

11 Adding Services

  1. In services.html, copy one complete <li id="…"> … </li> block inside the services list.
  2. Give it a new, unique id (lowercase, words separated by hyphens). The id is used by links such as services.html#interior-finishing.
  3. Change the icon (any file from assets/icons/), the number, the title, the description and the link.
  4. Update the hidden link text (<span class="visually-hidden">) so screen readers announce which service the link belongs to.
  5. Optionally add the service to the footer "Services" column and to the "All services" list in service-details.html.

Creating a page for each service

Duplicate service-details.html (for example commercial-construction.html). Update its title, meta tags, breadcrumb, content and images, and mark the matching link in the "All services" sidebar with aria-current="page". Then point the service card links to the new file and add the page to sitemap.xml.

12 Adding Projects

  1. In projects.html, copy one <li data-category="…"> block inside the list marked data-filter-list.
  2. Set data-category to residential, commercial, renovation or industrial.
  3. Update the image, category label, title, link and location.

Adding a new filter category

Add a button to the filter and use the same value in data-category on the matching projects. The filter script needs no changes.

<button class="filter__button" type="button" aria-pressed="false" data-filter-value="healthcare">Healthcare</button>

Case-study pages

Duplicate project-details.html for each project, update its content, and link to it from the project card and the homepage. The facts list, results and gallery are plain HTML blocks you can copy or remove. Update the "Next project" link at the bottom and add the page to sitemap.xml.

The homepage shows three featured projects. The first one is displayed large on desktop.

14 Contact Form Configuration

The forms on index.html and contact.html send messages to php/contact.php, which emails them to you with PHP's built-in mail() function. No external libraries or credentials are needed.

Setup (two minutes)

  1. In the php folder, make a copy of config.example.php and name it config.php.
  2. Open config.php and replace you@your-domain.example with the address that should receive messages: 
    'recipient_email' => 'office@yourcompany.com',
  3. Upload the site and send a test message. That's it.

How the form is protected

  • Validation twice: in the browser (form-validation.js) for quick feedback, and again on the server, where all input is cleaned and limited in length.
  • CSRF protection: a random token is stored in a secure session cookie (HttpOnly, SameSite=Strict) and must be sent with the form. The server also checks that the request comes from your own domain.
  • Spam protection: a hidden honeypot field, a minimum fill-in time and a per-visitor rate limit.
  • Header injection protection: line breaks and control characters are removed, the visitor's email is strictly validated, and only a validated Reply-To address and an encoded name reach the email headers.
  • No auto-reply: the form deliberately does not send confirmation emails to the address entered by the visitor, so it cannot be abused to send spam.

Testing locally

Set 'test_mode' => true in config.php and run php -S localhost:8000. The form shows the success message without sending an email. Set it back to false before publishing.

Changing the form fields

The select options (project type and budget) can be edited in the HTML only. To add a new field:

  1. Copy a form-field block in the form HTML, with a unique id, a name, an autocomplete value and an error element id="…-error".
  2. Optionally add a rule in validateField() in form-validation.js.
  3. In contact.php, read the new value in the $fields array, add a maximum length in $maxLengths, and add a row in build_message_body().

Deliverability tips

  • Use a from_email on the same domain as the website, and set up SPF and DKIM records for that domain with your host.
  • If messages land in spam or never arrive, ask your host whether mail() is enabled. Some hosts require SMTP; in that case you can integrate an SMTP library of your choice in contact.php (not included).

15 PHP Requirements

  • PHP 8.0 or newer (8.2+ recommended).
  • A working mail() function (available on most shared hosting).
  • PHP sessions enabled (standard).
  • Recommended extension: mbstring. The script falls back gracefully when it is missing.
  • No Composer, no database, no external libraries.

Local PHP development server

  • Windows: install PHP (or XAMPP / Laragon), open a terminal in the template folder and run php -S localhost:8000.
  • macOS: install PHP with Homebrew (brew install php), then run php -S localhost:8000 in the template folder.
  • Linux: install the php-cli package, then run php -S localhost:8000.

The built-in server does not send real emails unless your computer has a configured mail system, so use test_mode locally.

Hosting without PHP

The pages work on any static hosting, but the form needs PHP to send messages. On static hosting you can point the form's action to a form service of your choice (and remove form-validation.js or adapt it), or link visitors to your email address instead.

16 SEO Configuration

  1. Your domain: replace every https://www.example.com with your address (for example https://www.yourcompany.com) in all HTML pages (canonical, og:url, og:image, twitter:image), sitemap.xml, robots.txt and the structured data in index.html.
  2. Titles and descriptions: give every page a unique <title> (up to about 60 characters) and meta description (about 120–160 characters) that describe your real services and location.
  3. Structured data: update the JSON-LD block in the head of index.html (name, address, phone, email, opening hours). This is data, not JavaScript. Remove the block if you prefer.
  4. Sitemap: add new pages to sitemap.xml, update the <lastmod> dates and submit the sitemap in Google Search Console and Bing Webmaster Tools.
  5. Social sharing image: replace assets/images/social/og-image.jpg (1200 × 630 px) with an image that represents your brand.
  6. Error page: 404.html uses noindex and is excluded from the sitemap. The .htaccess file tells Apache to use it.

Write for people first: describe your services, locations and projects naturally, and avoid repeating keywords.

19 Accessibility

The template follows WCAG 2.2 level AA practices. Features include:

  • A "Skip to main content" link, semantic landmarks (header, nav, main, footer) and one <h1> per page with a logical heading order.
  • Full keyboard support:
    • visible focus outlines on every control;
    • a mobile menu with a focus trap, Escape to close and focus returned to the button;
    • an accordion with arrow-key navigation;
    • a portfolio filter built with real buttons and aria-pressed.
  • Colour contrast checked for all text (4.5:1, or 3:1 for large text) and form borders (3:1).
  • Forms: labels, autocomplete, error messages linked with aria-describedby, aria-invalid, and a live region for status messages.
  • Motion: the prefers-reduced-motion setting disables reveal effects, counters, transitions and smooth scrolling.
  • Interactive elements are at least 24 × 24 px (WCAG 2.2 target size), and most are 44 px or more.
  • Works without JavaScript: the navigation is shown as a list, FAQ answers are expanded and all content stays available.

Keep it accessible when editing

  • Write meaningful alt text for informative images. Use alt="" for decorative ones.
  • Keep the heading order and the one-h1-per-page rule.
  • Use descriptive link text. The hidden text in "Learn more" links tells screen-reader users where the link goes, so update it when you change the link.
  • Check contrast when you change colours (see Changing Colors).
  • When you add accordion items, give each button and panel new, unique ids.

Automated tests cannot catch everything. Test your final site with a keyboard and a screen reader.

22 Troubleshooting

The form says "not configured" or cannot send messages

  • Make sure php/config.php exists (a copy of config.example.php) and contains your real address in recipient_email.
  • If mail() fails, the error is written to your server's PHP error log. Ask your host whether mail() is enabled, or try 'use_envelope_sender' => true.
  • Opening the pages directly from your disk (file://) cannot run PHP. Use php -S localhost:8000 or real hosting.

"Your session has expired" or "blocked for security reasons"

  • Reload the page and send the form again. Tokens are valid for two hours.
  • If your site is reachable on several domains (for example with and without www), add them to allowed_origins, or redirect all visitors to one domain.
  • Do not set Referrer-Policy: no-referrer on your server. The form's origin check needs the browser's standard Origin or Referer header.

Messages arrive in the spam folder

Set from_email to an address on your own domain and configure SPF and DKIM with your host.

The 404 page looks unstyled

The 404 page uses relative paths. If your server shows it for addresses inside sub-folders (for example /folder/missing-page), change the asset paths in 404.html to root-relative paths (/assets/…). If the site is installed in a sub-folder, also update ErrorDocument in .htaccess.

My server uses Nginx instead of Apache

.htaccess files are ignored by Nginx. Add equivalent rules to your server block, for example error_page 404 /404.html; and a rule that denies access to /php/config.php. Make sure PHP-FPM handles .php files.

My CSS or JavaScript changes don't show up

Your browser or server may cache the old files. Refresh with Ctrl/Cmd + Shift + R, or add a version to the file link, for example assets/css/components.css?v=2.

Fonts look different

Check the Google Fonts link in the page head and your internet connection. If fonts are blocked (for example by a privacy extension or a Content Security Policy), the fallback system fonts are used. The layout is designed to stay intact in that case.

I enabled the Content Security Policy and something broke

The optional policy in .htaccess allows only your own files and Google Fonts. If you add analytics, maps, videos or other services, add their domains to the policy first.

An icon is black on a dark background

Icons turn white automatically inside elements with the theme-dark class. Elsewhere, add the icon--light class to the <img>.
